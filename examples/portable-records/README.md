# Portable Records Worked Example

This is a synthetic, runnable example of shared file support. It uses two fresh command-line
processes and a generated destination fixture. It is not a cross-AI-vendor test, an external
tracker connector, or a live migration. No private project data is included.

From the repository root, using Python 3.9+ on a local POSIX filesystem:

```sh
python3 examples/portable-records/demo.py .local-state/portable-records-demo
```

Choose a new/empty directory on each run. The demo creates a project-owned test workspace,
records a synthetic Desk ask and three work items, then uses a fresh process to record its
synthetic answer and release only the referenced blocker. It exports the full records/history
and compares a normalized destination fixture. All outputs stay in the chosen directory.

This example exercises a chosen conversion to the JSON binding. An existing TODO can instead
remain authoritative under the [Markdown work contract](../../docs/WORK-MANAGEMENT.md); this
demo is not a required adoption path or a Markdown parser.

Two items come from [the synthetic TODO snapshot](TODO.snapshot.md). The example copies that
source unchanged into the operational history folder and maps it explicitly. Unstated owners
and dates stay unconfirmed; the historical checkbox renders as operator-reported completion,
without invented proof. This illustrates a reviewed import, not an automatic parser for any
TODO format. The exported JSON preserves the references; linked source files require their
own retention and destination-access check.

Open the printed Desk and Work HTML paths in a browser or supported file preview. The same
source produces either view through the shared renderer. `.records/views.json` identifies
the source revision and generated bytes. The example's artifact index is a starter template;
complete it with the real project owners, access, pin, and recovery instructions before use.

Run the local contract checks:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

The tests cover empty startup, cooperating concurrent writers, stale updates, stable-ID
retention, duplicate retries, local Desk references, interrupted coupled writes, divergent
recovery, stale views, external-mode write retirement, and exact snapshot comparisons.
See [Qualification](QUALIFICATION.md) for evidence boundaries and remaining acceptance work.

The [profile](../../docs/PORTABLE-PROJECT-RECORDS.md),
[file helper](../../templates/project-records.md), and
[tracker handoff template](../../templates/tracker-binding-and-handoff.md) define the intended
project workflow. The existing Work Board pilot remains the single shared board implementation.
